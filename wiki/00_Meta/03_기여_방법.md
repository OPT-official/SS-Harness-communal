# 03_기여 방법

위키에 문서를 추가·수정해서 실제로 반영하는 절차. 이 위키는 GitHub 레포
`OPT-official/SS-Harness-communal`의 `wiki/` 폴더에 있다.

## 1. 어디에 넣을지부터

문서를 쓰기 전에 **`02_네이밍_넘버링_규칙.md`의 "판단 순서 4단계"** 로 위치·번호를 먼저 정한다.
맞는 템플릿이 있으면 `00_Meta/90_템플릿/`에서 복사해 시작한다.

## 2. 반영 절차 (git)

```bash
git clone https://github.com/OPT-official/SS-Harness-communal.git   # 처음 한 번
cd SS-Harness-communal

# 작업 브랜치 (권장)
git switch -c docs/무엇무엇          # 예: docs/meta-glossary
# → wiki/ 아래 문서 추가·수정

git add wiki/
git commit -m "docs: 무엇을 했는지 한 줄로"
git push -u origin docs/무엇무엇
# → GitHub 웹에서 Pull Request 열기
```

- 커밋 메시지: **한 줄로 명확하게.** `docs:` 접두 권장. `수정`, `업데이트` 같은 모호한 메시지 금지.
- 브랜치 이름: `docs/…`(문서), `feat/…`(기능), `fix/…`(수정).
- 상세 git 규칙(충돌 해결·squash merge 등)은 온보딩 레포의 Git 치트시트를 참조
  (`10_Onboarding/90_치트시트/` 로 옮겨올 예정).

## 3. main 직접 vs PR

- 원칙은 **PR(리뷰 1명)** — 공동 문서라 실수를 걸러낸다.
- 사소한 오타/링크 수정 등은 관리자 판단으로 main 직접 커밋 허용.
- (현재 이 레포는 main 브랜치 보호가 아직 설정되지 않은 상태 — 설정 후 PR 필수로 전환 예정.)

## 4. 규칙 자체를 바꾸고 싶을 때

넘버링/구조 규칙이 안 맞는 경우가 생기면 **문서를 임의로 어기지 말고** 먼저 이슈로 제안한다.
- 라벨: `docs`
- 합의되면 `00_Meta/02_네이밍_넘버링_규칙.md`를 고치고, 그 커밋에서 구조도 함께 정리한다.

## 5. 하지 말 것

- 과거 기수 폴더(`60_기수별활동/N기_…/`) 내용 수정 — 스냅샷이므로 보존.
- 상시 문서를 기수별로 복제 — 변경 이력은 git이 갖는다.
- 대용량 바이너리 원본 커밋 — 위치만 기록.
